# Passport Launcher 0.2.0 — 社区 BIN 导入

> 旧固定槽指南：0.4.0 容量及 SDK 兼容性以[共享存储](shared-storage.zh_CN.md)为准；额外分区依赖检查仍有效。

**当前界面版本：0.3.1。** 仅 BIN 安装、完整卸载、自动启动及 About 请参阅[界面指南](interface.zh_CN.md)。本页是 0.2.0 架构记录，保留旧安装包选择与自动启动限制的说明。

用户已反馈旧版 0.1.2 可以启动至菜单。这只确认旧版菜单启动成功，并不代表新版导入、网络或未修改社区应用已完成实机验收。

## 使用

产品名称改为 **Passport Launcher**。设备选择 **Install New App**，手机或笔记本连接 Wi-Fi **Passport Launcher**，密码 **aipassport**，访问 **http://192.168.168.1**。热点网关为 `192.168.168.1/24`，DHCP 使用同一子网；仅安装页面开启热点。

可选择 `.bin` 或已有 `.passport` 包。BIN 检查完成后显示建议名称与稳定应用 ID。不同应用使用不同 ID；更新时复用原 ID 才能保留设置。建议 ID 会去除可识别的文件名版本后缀，更新前仍应核对。原生 SDK 声明保留原 ID。

**Install / update** 将应用安装至可启动槽，不自动运行。设备长按 OK 退出安装页面，选中应用后按 OK 启动。未修改社区应用通过关机再开机或复位返回启动器；无法向已编译 BIN 新增应用内按键动作。SDK 应用保留原有返回操作。自动启动仍要求 SDK 健康确认，未修改 BIN 不提供此确认。

## 支持范围

- ESP32-C3、DIO / 80 MHz / 8 MB 镜像头、附加 SHA-256，以及正确段结构、校验和与哈希。社区固件支持 ESP-IDF 5.5 系列：`v5.5`、`v5.5.x` 及可选构建后缀。原生 ABI 1 SDK 包仍要求 ESP-IDF 5.5.3。
- 纯应用 BIN，或原 AI-Passport `nvs` / `phy_init` / `factory` 布局的完整 BIN；分区表 MD5 正确，初始 NVS/PHY 区为空。允许空白 Flash 填充。
- 浏览器从完整 BIN 提取应用代码，自动生成内部传输格式，交给现有流式安装器。不会安装上传镜像的引导器、分区表或未使用 Flash；用户无需自行转换或改名。
- **三个位置，每个应用代码最多 2,097,152 字节。** 完整文件因引导器和空隙可稍大，但提取出的代码必须放得下。普通移除后保留的数据位置仍占名额。
- 拒绝自定义资源、文件系统、数据或恢复分区、非空初始数据、签名/加密格式，以及过大应用。纯应用 BIN 不带分区表，无法仅靠镜像头证明不存在自定义分区依赖；需信任来源并实测。相同 ESP-IDF 版本不足以证明兼容。

使用 ESP32 [应用/OTA 启动机制](https://docs.espressif.com/projects/esp-idf/en/v5.5.3/esp32c3/api-reference/system/ota.html)，不是多任务应用沙箱。固件可以访问共享 Flash，不能保证任意二进制安全。

## 用户提供的三个文件

结果与[输入报告](community-input-results.json)中的哈希绑定。“通过”指解析、完整性、安装器及主机模拟的上下文/启动选择，**不是执行 ESP32 代码**。

| 文件 | 提取应用代码 | 结果 |
| --- | ---: | --- |
| `QSO-Vision_latest2.3.3.bin` | 1,828,608 字节 | 通过；标准完整镜像，ESP-IDF 5.5.3 |
| `Internet-Radio.bin` | 1,889,520 字节 | 通过；纯应用镜像，描述符为 ESP-IDF 5.5 |
| `pokemon.bin` / PokeWalk | 3,229,280 字节 | 阻止；超过槽容量且依赖自定义分区 |

PokeWalk 需要 `cardid`、`save_restore`、`wifi_config`、`pokewalk_store` 与 `recovery`，其中地址与启动器应用槽重叠。忽略分区表会造成数据风险，需要源码存储适配与容量规划。适配后可考虑较大槽的双应用布局，但会改变分区表，0.2.0 未实现。三个应用仅代码即合计 **6,947,408 字节**，超过当前 **6,291,456 字节应用区**，还未计入 PokeWalk 额外数据和恢复区，因此不能原样全部保留于当前布局。

## 设置与恢复

原生 SDK 应用继续使用 128 KiB 私有 NVS。未修改社区应用通过运行时分区表使用 **16 KiB 默认 NVS**，见 [ESP-IDF NVS API](https://docs.espressif.com/projects/esp-idf/en/v5.5.3/esp32c3/api-reference/storage/nvs_flash.html)。启动前从各自 128 KiB 私有区恢复默认 NVS 原始字节；回到启动器后先保存。社区应用获得的默认 NVS 容量并非 128 KiB。

上下文日志先于启动器默认 NVS 初始化执行。RESTORING 表示恢复未完成，保留旧快照；ACTIVE 保存应用最新字节；SAVED 避免将清空一半的数据重新覆盖快照；IDLE 允许启动器初始化无线校准数据。快照校验 ID 与 SHA-256。模式信息独立保存在元数据区，使旧 ABI 1 应用仍能读取版本 1 注册表；模式丢失时不会把社区镜像当作 SDK 应用启动。保留 ID 时禁止改变存储模式，需明确删除应用及设置后才可重新分配。

复制默认 NVS 会增加切换时的 Flash 写入。这不是对任意原始 Flash 写入的隔离。主机测试覆盖 I/O 前后失败与部分原始擦写，不模拟真实 NVS 页恢复或物理掉电。切换、设置保留、无线、堆栈及掉电行为仍需实测。

## 从 0.1.2 升级

使用提供的 **Passport-Launcher-0.2.0-full.bin**，在[官方网页刷写工具](https://ai-passport.folotoy.cn/tools/web-flasher/)写入 **0x0**。保留更新时不要选择全片清除/擦除。分区表不变，镜像在首个应用槽 `0x190000` 之前结束，不覆盖已有应用、元数据和私有数据。合并镜像会重置启动器默认 NVS，替换启动器引导器、分区表与应用区域。这是启动器更新，不能在启动器内当另一个应用安装。保留更新不要使用旧的 8 MB 全新安装镜像。

升级后确认新名称、热点密码和地址，上传原始 QSO 与 Internet Radio BIN，分别启动并保存不同设置，交替关机开机后检查保留情况；确认 Pokémon 在上传前被拒绝。本主机未刷写或执行这些文件。编译与主机检查不等于实机验收。

内部 SDK 符号、ID 与 `PassportOS` 构建/归档名称为兼容旧应用而保留；设备、网页、热点与交付镜像使用 Passport Launcher 名称。
