# 0.4.2 社区 BIN 兼容性

之前的导入器只接受一种完全相同的合并分区表，因此会在上传前拒绝其他有效社区固件。它没有按应用名设置白名单。0.4.2 改为解析并校验实际分区表，支持不同应用偏移、不同大小的 NVS，以及额外私有数据、资源和 test/recovery 分区。

| 作者提供的原文件 | 应用代码 | 私有区 | 最低占用（含扇区取整） | 主机安装/启动选择模型 |
| --- | ---: | ---: | ---: | --- |
| `badminston score.bin` | 1,429,488 字节 | 204,800 字节 | 1,634,304 字节 | 通过 |
| `pokemon.bin` | 3,229,280 字节 | 1,507,328 字节 | 4,739,072 字节 | 通过 |
| `qiannian-jiazu-v3.4-full.bin` | 1,601,136 字节 | 180,224 字节 | 1,781,760 字节 | 通过 |

羽毛球计分应用从 `0x20000` 开始，使用 64 KiB NVS；千年家族还需要 `cardid`；Pokémon 还需要 `cardid`、`save_restore`、`wifi_config`、`pokewalk_store` 和 1 MiB recovery。导入后这些区域按原标签、类型、大小映射到该应用独占的空间，不会按原固件的绝对地址直接覆盖其他应用。原文件未包含的数据区按擦除态初始化，仍计入占用。

三者最低占用合计 **8,155,136 字节**，超过 **6,684,672 字节共享池**，不能同时全部装下；还需考虑对齐和碎片。设备在上传前检查实际空间，原有 QSO Vision 和 Internet Radio 的安装方式继续保留。

安装完成前检查代码、私有初始内容和写入读回结果。更新保留私有存档；同一应用 ID 的分区布局改变时拒绝更新，需要先卸载。确认卸载会擦除代码、NVS、资源与 recovery 等全部占用后释放空间。一次性启动票据与引导清表恢复机制仍保留。

这些检查使用真实 BIN、生产安装器和引导钩子的主机模型，**没有运行 ESP32 指令，也没有连接实机**。通过不等于实机运行验证。使用分区 API 的应用可利用重映射；硬编码物理地址、自刷引导程序、独立 OTA 启动链、签名/加密镜像或不兼容硬件仍需单独适配。最多支持八个附加分区。recovery 区域被保留，但应用重启仍返回启动器，不接管原应用的独立恢复启动链。

原生 SDK 2 应用与扩展布局混用时应使用本版本 core/model 重编译；旧模型会拒绝非零扩展字段。装入新布局应用后，不要保留注册表降级到 0.4.1。

## 升级已有 0.4.0 / 0.4.1

1. 断电重启，取消自动启动，停留在启动器菜单，让上次社区应用的 NVS 快照保存完成。
2. 用网页 USB 刷机工具，将 `Passport-Launcher-0.4.2-update.bin` 写入 **0x0**，**关闭整片擦除**。短升级镜像更新启动器和引导程序，在 `0x190000` 共享区之前结束，保留应用与私有存档。
3. 进入 **Install a ROM**，手机或电脑连接 **Passport Launcher**，密码 **aipassport**，打开 **http://192.168.168.1**。重新加载网页以使用新导入器，选择原始社区 BIN，等待安装完成，再从设备选择启动。

独立的 `fresh.bin` 会清除整个 8 MiB 闪存，只用于明确的全新安装或旧 0.1–0.3 迁移。启动器固件请使用 USB 刷机工具，不要上传到自己的应用安装页面。
