# 生命周期验证：0.1.2

主机测试将**真实应用管理器、SDK 与引导钩子**链接在一起，使用持久内存后端模拟 Flash、应用值、元数据和启动选择。SHA-256 使用 OpenSSL，而不是固定结果桩。验证模拟复位后的控制流和数据归属，不执行 ESP32 应用机器码，也不代表电气掉电恢复已通过。

## 已验证场景

| 操作 | 主机验证内容 |
| --- | --- |
| 首次安装 | 镜像完整后才发布 READY，默认进入启动器 |
| 独立应用 | 两个身份通过真实 SDK 使用相同 `counter/value` 键，跨切换保留不同值 |
| 启动/返回 | 管理器保存待确认状态、设置启动选择并发票据；引导器消费票据；SDK 返回无新票据而进入 factory |
| 健康/自动启动 | 未确认时保留待确认标志；健康确认后允许配置的正常上电自动启动；普通返回仍进菜单 |
| 容量 | 三个位置满时拒绝第四应用，普通移除仍保留 ID 位置 |
| 移除重装 | 同 ID 复用原位置，并保留仅移除代码后的设置 |
| 更新 | 同 ID 新镜像保留私有值；识别跨 4 KiB 读取边界的声明 |
| 删除及重分配 | 擦除所选私有值后才可交给新 ID，另一应用的数据保持不变 |
| 镜像损坏 | 字节变化由真实 SHA 检查拒绝，启动选择尚未改变 |
| 元数据丢失 | 注册表缺失且仍有应用/私有数据时进入恢复，不清空数据 |
| 不确定写入 | 在更新/删除/启动的每个 I/O 边界写入前后失败，重新加载及重试仍保持归属 |
| 立即重试 | 每个更新故障后可直接在同一管理器实例重试，不要求先复位 |

当前小型协议样本覆盖 **106 个更新**、**8 个删除**、**7 个启动** I/O 边界，分别注入写入前及写入后错误。即使 OTA 选择已持久化，启动报错也不会发票据，随后软件复位仍进启动器。其他应用值和模拟常驻启动器区不变。另有迁移、包解析、SDK 分区边界及浏览器测试。

后端假定完整 NVS 记录可持久化，在 API 操作周围注入错误，不模拟真实编程撕裂、NVS 页面回收、发布者身份认证、无线、显示或芯片修订检查。这些仍须独立验收。小型协议样本**不是可执行示例应用，不能安装到设备**，仅生成在临时测试目录，不进入交付包。真正的硬件测试候选仍是单独编译的计数器和 QSO 包。

## 自动启动输入修正

原菜单可能在五秒到期时先决定启动，再处理已排队输入。新的控制器优先处理输入，即使 UI 任务延迟到截止后才发现。按键回调记录单调事件时间；排空队列时按事件时间消费取消动作，避免绘图等延迟使同一次取消动作的 CLICK 被当成新的手动启动。

针对测试覆盖截止时输入、任务延迟、完整按下/释放/CLICK 抑制以及只自动启动一次。真实消抖和临界时刻响应仍须板子。另外，安装服务关闭失败时 UI 保留原页面，方便重试清理，不提前显示主菜单。

## 构建与应用独立

主机检查需要 C 编译器、Python 3、Node.js、OpenSSL 开发头及库 `libcrypto`。固件仍用 ESP-IDF mbedTLS，OpenSSL 仅链接主机测试。运行常规 `bash tools/validate.sh`。

0.1.2 改变启动/输入处理和测试，分区表、注册表模式、包 ABI、私有数据布局不变。复用已验证兼容应用包及匹配 ELF。QSO Vision 仍是单独安装的参考/测试应用；启动器有设置导入支持，没有 QSO 无线电和应用 UI 源码。本阶段未刷写硬件。
