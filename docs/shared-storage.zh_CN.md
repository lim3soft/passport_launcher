# 0.4.0 共享 Flash

> 0.4.1 保持此布局/注册表，仅增加独立可选启动目标 NVS 键。按指南使用短升级镜像可保留共享应用区；完整全新安装镜像仍为独立、会清除数据的文件。

所有者已同意使用全新存储布局。本版替代截至 0.3.1 的固定槽架构，移除社区下载辅助工具，仅通过本地 BIN 上传安装。

8 MiB 布局保留 `0x0–0xffff` 给引导/分区表/系统区、`0x10000–0x18ffff` 给常驻 factory 启动器、`0x7f0000–0x7fffff` 给 64 KiB 元数据 NVS。共享池 `0x190000–0x7effff` 共 **6,684,672 字节 / 6.375 MiB**。无需额外执行槽或重复仓库镜像，每个应用直接保存在独立分配区。

代码长度向上取整到 4 KiB，每个应用另拥有 128 KiB 私有 NVS。代码起始地址按 [ESP-IDF 要求对齐至 64 KiB](https://docs.espressif.com/projects/esp-idf/en/v5.5/esp32c3/api-guides/partition-tables.html)。空池扣除一个设置预留后最多可分配 6.25 MiB 代码，但仍须满足镜像及地址/内存要求。这是 Flash 预算，不是实机执行证明。没有人为的 2 MiB 镜像限制。应用索引支持 16 个身份，与 SDK 的 16 个 OTA 子类型对应；普通社区应用通常先耗尽 Flash。不承诺任意数量的完整固件。

纯逻辑 first-fit 分配器不移动其他应用或其数据。更新可回收/重新分配自己的代码，保留原私有数据地址。完整 SHA-256 和 SDK 镜像验证通过前不可启动。碎片可能使最大可安装 ROM 小于剩余总量。设备和网页显示剩余空间，`/api/capacity` 另返回总池、已分配、有效载荷及扣除新设置预留后的最大 ROM。`/api/preflight` 先做只读元数据检查，实际安装在管理器锁内重复验证。

v2 NVS 注册表记录所有者、地址、初始化和生命周期。先提交 INSTALLING 再擦除；新私有区必须擦除后才能 READY，未成功时重试初始化。更新保留已初始化设置。完整卸载先提交不可启动墓碑及私有区未初始化标记，再擦除代码/数据并释放所有权。部分失败可重试。元数据提交失败后重新读取所有权；不能确认则禁止继续破坏性操作。社区默认 NVS 快照和恢复日志仍绑定稳定身份。

factory 启动只暴露永久分区表，启动器通过 ESP-IDF API 注册已验证的代码/数据区域。32 字节一次性 RTC 票据携带所选地址和校验。自定义引导器在任何分区表操作前消费并清除票据，生成包含永久区域及所选应用/数据的临时表，验证 MD5 与回读后作为 OTA 0 启动。原生 SDK 根据稳定 ID 和实际运行区域识别应用，不再假设固定地址。

其他复位均在 **SDK 读取表之前**重建永久 factory 表，因此中断的表擦写不依赖损坏的表定位启动器。前提是引导器与 factory 代码完整；USB ROM 刷写及任意原始 Flash 写入仍可覆盖它们。未启用安全启动、Flash 加密、eFuse 修改或硬件隔离。

进入应用及返回 factory 分别可能擦写一次分区表扇区；内容相同则不写。相比固定表会增加磨损，实机寿命及实际断电恢复尚未验证。启动仍验证镜像哈希、原生身份/存储模式、一次性票据和冷启动取消策略。看门狗、异常和普通应用重启进入启动器。

SDK 1 应用必须按 SDK 2 及 32 字节 RTC 预留重新编译，拒绝静默使用旧注册表/地址协议。社区 ESP-IDF 5.5.x 的应用 BIN 和支持的标准合并 BIN 无需 SDK 集成。额外文件系统/资源分区、不兼容 Flash 参数和绝对地址假设仍需适配。Pokémon / 应用 1434 虽然代码能放入空池，仍因自定义分区依赖被拒绝。

全新安装 BIN 明确填充到 8 MiB，清空所有旧应用/数据/元数据。这是本次迁移已同意的数据清除，不能当作保留设置的升级镜像。旧版归档和迁移文档仅描述历史布局，不适用于 0.4。

主机验证覆盖超过 2 MiB 的流式安装、第四应用的私有数据持久化、10,000 次分配操作、容量计量、碎片、其他应用保护、元数据故障与重试、默认 NVS 部分写入和分区表中断。48 KiB LVGL 池测试完整 16 项应用库。这些测试不模拟 ESP32 机器码执行、实际寿命或实机 RF/堆/栈/断电行为。
